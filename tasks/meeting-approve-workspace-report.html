At a glance

  • ✓ Scheduling a meeting follow-up used to fail the first time and work the second. It now works the first time.
  • ✓ The bulk “Move schedulable items to today” button hit the same error once per fresh follow-up. It no longer does.
  • ✓ Every failed click quietly left a duplicate follow-up parked under the meeting. Those stop being created.
  • ✓ The real cause was one line deep in the database layer: a newly created item came back without knowing which workspace it belonged to, so the meeting code refused the item it had just made.
  • ✓ Two more places had the same gap and are fixed in the same pass, so a whole class of “this item has no owner” bugs is closed, not just this one symptom.
