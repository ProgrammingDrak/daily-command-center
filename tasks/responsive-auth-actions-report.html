Narrow windows now keep important task actions visible, and Google sign-in returns to a dedicated verification state instead of briefly looking unsuccessful.

What was broken

At smaller browser widths, the layout removed actions that were still useful and could still fit, including Delete. After Google OAuth, the page could also flash the login form while the app created its own session, making a successful login look like it failed.

What is fixed

Task actions stay reachable

Bounty, Actions, and Delete remain visible as 38px controls at 735px and 390px. Notes and Delete also live in the radial menu for both tasks and meetings.

OAuth shows honest progress

The return URL enters a pre-paint verification state immediately. A friendly recovery message returns the user to login if Clerk cannot finish within 10 seconds.

How to confirm
  1. Narrow the command center below 760px and confirm Bounty, Actions, and Delete remain visible.
  2. Open Actions and confirm Notes and Delete are present for a task or meeting.
  3. Use Continue with Google and confirm the verification card appears during the return instead of the login form.
Who benefits
  • Mobile users can manage and remove tasks without switching views.
  • Split-window users keep the same action surface as full-width desktop users.
  • Anyone using Google sign-in gets clear confirmation that authentication is still progressing.
Summary

This bug fix preserves the action set across responsive breakpoints and makes the login experience fit inside its card. It also adds a purpose-built verification state around the Clerk-to-DCC session handoff.
